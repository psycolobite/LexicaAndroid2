1. L'Architecture Organisationnelle : "Hierarchical AI-Agent Swarm" (Essaim d'Agents Hiérarchisé)
C'est le nom technique de votre organisation de travail.
Concept : Vous (le "Chef d'Orchestre") êtes le Superviseur. Vous déléguez des tâches spécifiques à des "travailleurs" spécialisés (les Agents dans VS Code, Android Studio, etc.) qui ne se marchent pas dessus.
Le Pattern : C'est un "Hub-and-Spoke" (Moyeu et Rayons). Vous êtes le moyeu central, et chaque éditeur ouvert est un rayon qui traite une tâche en parallèle avant de ramener le résultat vers vous.
2. Le Workflow : "Feature Branch Workflow" (piloté par la Doc)
C'est la méthode que nous utilisons pour gérer le code.
Concept : On ne touche jamais à la branche principale (main) directement. Chaque nouvelle fonctionnalité (le "Quoi") est d'abord une branche ou un fichier de spécification (le "Comment") avant d'être fusionnée.
Spécificité ici : C'est du "Documentation-Driven Development" (DDD). On écrit d'abord la doc (features.md, specs) et le code n'est qu'une conséquence de la documentation.
3. L'Architecture de l'Application : "Clean Architecture + MVVM"
C'est la structure des dossiers dans votre code Android (data, domain, presentation).
Clean Architecture : Séparation stricte en couches (Couche de Données, Couche Domaine/Métier, Couche Présentation/UI). Cela rend l'appli testable et robuste.
MVVM (Model-View-ViewModel) : La façon dont l'interface (Compose) parle aux données sans se mélanger les pinceaux.
En résumé
Vous avez construit une "Clean Architecture Android" développée via un workflow "Documentation-Driven" orchestré par un système "Multi-Agents Supervisé".
